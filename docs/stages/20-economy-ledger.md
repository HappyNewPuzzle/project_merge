# 20단계 — 통합 경제 증감 원장

## 단계 목표

현재 에너지와 코인 잔액만으로는 장애나 고객 문의에서 어떤 기능이 값을 바꿨는지 알기
어렵습니다. 20단계는 모든 신규 경제 변경을 사유별 불변 원장에 기록하고 플레이어가 최근
내역을 조회할 수 있게 합니다.

## 원장 데이터

`economy_ledger_entries`의 각 행은 다음 값을 가집니다.

- `resource`: `energy` 또는 `coins`
- `reason`: 서버가 정의한 안정적인 변경 사유
- `delta`: 양수 지급·회복, 음수 소비
- `balance_after`: 변경 직후 잔액
- `economy_revision`: 변경 결과 경제 revision
- `reference_id`: 관련 아이템·퀘스트·선물·감사 작업 식별자
- `occurred_at_utc`: 서버 UTC 발생 시각

원장은 애플리케이션에서 수정·삭제 API를 제공하지 않습니다. 빠른 현재 상태 조회는 기존
`player_economies`를 사용하고, 원장은 추적과 복구 근거로 사용합니다.

## 기록되는 사유

| resource | reason | 발생 기능 |
|---|---|---|
| energy | `energy.recharged` | 소비/선물 처리 시 DB에 확정된 자연 회복 |
| energy | `generator.energy_spent` | 기존 및 서버 권위형 생성기 소비 |
| energy | `friend.energy_received` | 친구 에너지 선물 수신 |
| coins | `daily_reward.claimed` | 일일 코인 보상 |
| coins | `quest.reward_claimed` | 퀘스트 보상 수령 |
| coins | `board_item.sold` | 보드 아이템 판매 |
| coins | `admin.coins_adjusted` | 관리자 코인 지급·회수 |

자연 회복은 조회 시 계산되는 투영 값만으로 원장을 만들지 않습니다. 생성기 사용이나 친구
선물처럼 `PlayerEconomy`가 실제 DB에 회복분을 확정하는 트랜잭션에서만
`energy.recharged`를 기록합니다.

## 원자성

각 원장 행은 원인이 되는 경제 변경과 동일한 `SaveChanges`에 추가됩니다. 예를 들어 아이템
판매는 아이템 제거, 보드 revision, 코인 지급, 경제 revision, 판매 멱등 영수증과 판매 원장
행이 모두 성공하거나 모두 롤백됩니다.

기존 기능의 멱등 영수증과 유니크 키가 재시도를 차단하므로 원장도 중복 생성되지 않습니다.
원장 자체를 잔액 변경 명령으로 사용하지 않고 성공한 도메인 변경의 결과로만 추가합니다.

## 조회 API

```http
GET /api/v1/economy/ledger?limit=50
Authorization: Bearer {accessToken}
```

- 최신 발생 시각 순으로 반환
- 기본 50건
- 최소 1건, 최대 100건으로 서버에서 제한
- 인증된 본인의 행만 조회
- 아직 변경 내역이 없으면 빈 배열 반환

정지 계정은 다른 플레이 API와 동일하게 HTTP 403입니다.

## MySQL 변경

마이그레이션 `20260815025617_AddEconomyLedger`가 다음을 추가합니다.

- `economy_ledger_entries` 테이블
- 0이 아닌 delta CHECK 제약
- 플레이어와 발생 시각 복합 조회 인덱스
- 플레이어 삭제 시 원장도 정리되는 외래 키

이번 단계 배포 이전의 과거 잔액 변경은 소급 생성하지 않습니다. 기존 현재 잔액을 임의의
사유로 추정해 백필하면 감사 신뢰도가 떨어지므로, 필요하면 별도 검증된 오프라인 백필
절차를 설계해야 합니다.
