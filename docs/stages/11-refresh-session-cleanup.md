# 11단계 — Refresh session 백그라운드 정리

## 단계 목표

회전, 로그아웃, 만료로 더 이상 사용할 수 없는 refresh session이 MySQL에 무기한
쌓이지 않도록 서버 내부 백그라운드 작업으로 정리합니다. 보안 사고 분석에 필요한
기간은 유지하고, 작은 배치와 실행 상한으로 게임 요청 DB 부하를 제한합니다.

## 삭제 대상과 보존 정책

기본 보존 기간은 7일입니다. 현재 UTC 시각에서 보존 기간을 뺀 경계보다 다음 값이
오래된 session만 삭제합니다.

- `expires_at_utc`: 이미 만료된 토큰도 만료 후 7일간 유지
- `revoked_at_utc`: 회전·로그아웃·재사용 탐지 증적을 폐기 후 7일간 유지

아직 유효한 session과 최근 폐기 session은 삭제하지 않습니다. 보존 기간을 두면 토큰
재사용 공격 조사와 인증 장애 분석에 필요한 family 계보와 폐기 사유를 확인할 수
있습니다.

## 배치 처리

한 번에 전체 테이블을 삭제하지 않습니다. 기본 설정은 다음과 같습니다.

```json
"RefreshSessionCleanup": {
  "IntervalMinutes": 60,
  "RetentionDays": 7,
  "BatchSize": 500,
  "MaxBatchesPerRun": 10
}
```

한 주기에는 최대 `500 × 10 = 5,000`행만 삭제합니다. 오래된 `expires_at_utc` 순으로
처리해 장기 적체부터 줄입니다. 마지막 배치가 500행보다 작으면 추가 DB 조회 없이
종료합니다.

환경 변수에서는 `RefreshSessionCleanup__IntervalMinutes`처럼 이중 밑줄 형식을
사용합니다. 서버는 다음 범위를 벗어난 설정이면 시작을 거부합니다.

- 주기: 1~1,440분
- 보존: 1~90일
- 배치 크기: 10~5,000행
- 실행당 배치: 1~100회

## 서버 수명과 장애 처리

`RefreshSessionCleanupWorker`는 `BackgroundService`로 실행됩니다.

1. 서버 시작 직후에는 정리하지 않고 한 주기를 기다립니다.
2. 매 주기 새 DI scope와 새 `MergeGameDbContext`를 생성합니다.
3. 삭제된 행이 있을 때만 구조화 정보 로그를 남깁니다.
4. 일시적인 MySQL 오류는 오류 로그를 남기고 다음 주기에 재시도합니다.
5. 서버 종료 취소 신호를 받으면 추가 작업 없이 정상 종료합니다.

여러 서버 인스턴스가 같은 행을 선택할 수 있지만 삭제 경합은 concurrency 예외로
처리하고 다음 배치를 다시 조회합니다. 정리 작업은 토큰 발급·회전 API의 성공 여부를
막지 않으며, 실패해도 서버 프로세스를 종료하지 않습니다.

## 로그와 모니터링

삭제가 발생하면 다음 구조화 필드가 기록됩니다.

```text
Old refresh sessions cleaned. DeletedCount=500
```

토큰 원문, 해시, 플레이어 ID는 정리 로그에 포함하지 않습니다. 운영 환경에서는 오류
로그 연속 발생과 `refresh_token_sessions` 테이블 행 수 증가율을 경보 대상으로
설정합니다.

## 데이터베이스 변경

11단계는 10단계의 기존 인덱스와 열을 사용하므로 새 마이그레이션이 없습니다.
`expires_at_utc`, `revoked_at_utc` 조건으로 후보를 찾고 제한된 행만 추적 삭제합니다.
EF 모델과 마지막 마이그레이션의 동기화 검사를 통해 스키마 누락이 없음을 확인합니다.
