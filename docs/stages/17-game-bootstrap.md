# 17단계 — 게임 부트스트랩 및 초기 동기화 API

## 단계 목표

Unity가 로그인 직후 보드, 경제, 퀘스트, 소셜, 생성기 API를 순차 호출하던 과정을 하나의
요청으로 통합했습니다. 새 플레이어 또는 이전 스키마에서 넘어온 플레이어에게 누락된
상태가 있으면 한 트랜잭션으로 생성한 뒤 일관된 전체 스냅샷을 반환합니다.

## API

```http
POST /api/v1/game/bootstrap
Authorization: Bearer {accessToken}
```

POST이지만 같은 플레이어에게 반복 호출해도 상태가 중복 생성되지 않는 멱등 초기화
동작입니다. 정지 계정은 기존 미들웨어에서 HTTP 403으로 차단됩니다.

응답에는 다음 값이 포함됩니다.

- `serverTimeUtc`: 쿨다운과 일일 초기화의 기준이 되는 서버 UTC 시각
- `contentVersion`: 클라이언트 콘텐츠 캐시 비교용 버전
- `player`: 플레이어 ID, 표시 이름, 계정 생성 시각
- `board`: 5×7 전체 보드, 아이템, revision
- `economy`: 에너지, 코인, 자연 회복 시각, revision
- `generators`: 모든 활성 생성기의 충전·쿨다운 상태
- `quests`: 현재 활성 퀘스트 목록
- `social`: 친구 코드, 친구 목록, 오늘 에너지 선물 여부

## 원자적 지연 초기화

다음 상태 중 없는 것만 생성합니다.

1. 시작 아이템 2개를 가진 플레이어 보드
2. 에너지 100과 코인 0인 경제 상태
3. 첫 머지 퀘스트
4. 8자리 공개 친구 코드가 있는 소셜 프로필
5. 서버 카탈로그에 등록된 모든 생성기의 최대 충전 상태

모든 추가 엔티티는 한 번의 `SaveChanges`로 저장됩니다. 하나라도 유니크 키 또는 동시성
충돌이 나면 전체 트랜잭션을 롤백하고 DB 최신 상태를 다시 읽어 최대 5회 재시도합니다.
따라서 보드만 있고 경제는 없는 부분 초기화 응답을 반환하지 않습니다.

이미 존재하는 상태는 덮어쓰지 않습니다. 보드 revision, 에너지, 코인, 퀘스트 진행도,
친구 코드와 생성기 충전량이 로그인할 때 초기값으로 돌아가지 않습니다.

## 친구와 생성기 조회

친구 목록은 친구 관계 양쪽 방향을 정규화해 조회하고, UTC 오늘 발송한 에너지 선물을
표시합니다. 생성기 카탈로그는 `GetAll()` 계약을 제공해 부트스트랩이 특정 생성기 ID를
하드코딩하지 않습니다.

현재 임시 콘텐츠 버전은 `2026.08.15.1`입니다. 18단계에서 아이템과 생성기 정의를
공개하는 버전형 콘텐츠 카탈로그로 이 값을 이동합니다.

## 오류 처리

- JWT 없음/만료: HTTP 401
- 정지 계정: HTTP 403 `account_suspended`
- JWT의 플레이어가 삭제됨: HTTP 404
- 5회 연속 초기화 충돌: 전역 Problem Details HTTP 500과 trace ID

## 단계 완료 검증

2026-08-15에 다음 항목을 확인했습니다.

- 새 플레이어의 보드·경제·퀘스트·소셜·생성기 단일 초기화 테스트
- 반복 호출 시 데이터와 revision 무변경 테스트
- 삭제된 인증 플레이어 404 서비스 결과 테스트
- 부트스트랩 OpenAPI 경로와 응답 DTO 검사
- 전체 자동 테스트 62개 통과
- Release 빌드 경고 0개, 오류 0개
- 새 DB 스키마가 필요하지 않아 마이그레이션 변경 없음

## Unity 권장 흐름

1. 게스트 로그인 또는 refresh로 액세스 토큰을 확보합니다.
2. `POST /api/v1/game/bootstrap`을 호출합니다.
3. 응답의 보드·경제·퀘스트·소셜·생성기 상태로 각 로컬 저장소를 교체합니다.
4. `serverTimeUtc`와 기기 UTC 차이를 계산해 서버 쿨다운 표시를 보정합니다.
5. `contentVersion`이 로컬 캐시와 다르면 18단계 콘텐츠 API를 호출합니다.
