# 18단계 — 버전형 서버 콘텐츠 카탈로그

## 단계 목표

Unity가 아이템 이름, 머지 단계, 생성기 비용과 쿨다운을 별도로 하드코딩하지 않도록 서버의
실제 도메인 정의를 공개 API로 제공합니다. 콘텐츠 버전과 HTTP ETag를 이용해 변경된 경우에만
다시 내려받을 수 있습니다.

## 공개 API

```http
GET /api/v1/content/catalog
```

로그인 전 타이틀 화면에서도 캐시를 준비할 수 있도록 JWT를 요구하지 않습니다. 응답에는
계정 정보나 운영 비밀이 없고 공개 게임 규칙만 포함됩니다.

응답 구조:

- `version`: 현재 콘텐츠 계약 버전
- `board`: 가로·세로·전체 슬롯 수
- `economy`: 최대 에너지, 회복 간격, 일일 보상, 친구 선물량
- `itemChains`: 계열 ID와 레벨별 이름·최대 단계 여부
- `generators`: 생성 아이템, 에너지 비용, 최대 충전량, 충전 회복 간격

현재 카탈로그는 다음 핵심 규칙을 반환합니다.

- 5×7, 총 35슬롯 보드
- 최대 에너지 100, 300초마다 에너지 1 회복
- 일일 코인 보상 50, 친구 에너지 선물 5
- `garden` 아이템 1~5레벨
- `garden` 생성기: 1레벨 생성, 에너지 1, 최대 충전 5, 30초 회복

## 단일 규칙 원천

`IItemCatalog.GetAll()`과 `IGeneratorCatalog.GetAll()`을 추가했습니다. 콘텐츠 API는 별도
복사본이 아니라 보드 머지와 생성 서비스가 실제 사용하는 같은 카탈로그를 열거합니다.

생성기 `EnergyCost`도 `GeneratorDefinition`으로 이동했습니다. 서버 권위형 생성 서비스는
카탈로그 비용을 사전 검증과 실제 차감에 모두 사용합니다. 기존 호환 생성 API는 기본 비용
1을 유지합니다.

## 버전과 캐시

현재 버전은 `2026.08.15.1`입니다. 아이템 단계, 생성 결과, 비용, 충전 시간 또는 공개 경제
규칙이 바뀌면 `GameContentVersion.Current`도 반드시 올립니다.

응답 헤더:

```http
ETag: "2026.08.15.1"
Cache-Control: public,max-age=300,must-revalidate
```

Unity가 같은 ETag를 `If-None-Match`에 보내면 서버는 본문 없는 HTTP 304를 반환합니다.
부트스트랩의 `contentVersion`과 로컬 캐시 버전이 같으면 콘텐츠 요청 자체를 생략할 수도
있습니다.

## Unity 캐시 흐름

1. 로컬 콘텐츠 JSON과 ETag를 읽습니다.
2. 부트스트랩 `contentVersion`이 로컬 버전과 같으면 캐시를 사용합니다.
3. 다르면 `If-None-Match`와 함께 콘텐츠 API를 호출합니다.
4. HTTP 200이면 응답과 새 ETag를 원자적으로 로컬 저장합니다.
5. HTTP 304면 기존 캐시를 유지합니다.
6. 콘텐츠가 없고 네트워크도 실패하면 게임 플레이 진입을 막고 재시도 UI를 표시합니다.
