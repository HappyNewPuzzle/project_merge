# 서버 배포 및 롤백 런북

## 배포 전 조건

- `main`의 `server-ci`가 모두 통과해야 합니다.
- 배포 커밋, 서버 버전, 콘텐츠 버전과 최소 클라이언트 버전을 변경 기록에 남깁니다.
- MySQL 백업을 생성하고 복구 테스트를 통과한 최근 백업이 있는지 확인합니다.
- 새 마이그레이션의 `Up`과 `Down` SQL, 예상 테이블 잠금 시간을 검토합니다.
- JWT, 관리자 키와 DB 비밀번호는 배포 플랫폼의 비밀 저장소에서만 주입합니다.

## 권장 배포 순서

1. 트래픽이 낮은 시간을 선택하고 담당자·롤백 결정권자를 지정합니다.
2. `scripts/verify-release.ps1`로 배포 후보를 다시 검증합니다.
3. 새 Docker 이미지를 커밋 SHA 태그로 빌드하고 변경 불가능한 레지스트리에 푸시합니다.
4. 기존 서버와 동일한 MySQL 백업을 생성합니다.
5. 별도 마이그레이션 작업에서 `dotnet ef database update`를 한 번 실행합니다.
6. 새 이미지 인스턴스 하나를 기동하고 `/health`, `/api/v1/version`, OpenAPI를 확인합니다.
7. 소량 트래픽을 새 버전에 전달해 5xx, DB 지연, 401/403/426 비율을 확인합니다.
8. 문제가 없으면 점진적으로 전체 인스턴스를 교체합니다.
9. 생성·보드 액션·판매의 synthetic 계정 흐름과 경제 원장을 확인합니다.
10. 배포 SHA, 마이그레이션, 시작·완료 시각과 검증 결과를 운영 기록에 남깁니다.

애플리케이션 시작 시 자동 마이그레이션하지 않습니다. 여러 인스턴스가 동시에 DDL을 실행하는
경쟁과 예측하지 못한 장시간 잠금을 피하기 위해 배포 작업에서 명시적으로 한 번만 적용합니다.

## 롤백 판정

다음 중 하나면 트래픽 확대를 중단합니다.

- `/health` 비정상 또는 MySQL 연결 실패
- 기준 대비 5xx나 DB 지연 급증
- 경제 원장의 delta와 실제 잔액 불일치
- 다수의 정상 클라이언트가 426을 받음
- 새 마이그레이션 이후 핵심 API 쓰기 실패

코드만 되돌릴 수 있고 새 스키마가 이전 코드와 호환되면 이전 이미지 SHA로 트래픽을
되돌립니다. 스키마가 비호환이면 무조건 `Down`을 실행하지 않습니다. 새 데이터 손실 여부를
검토하고 전진 수정, 검증된 Down, 백업 복원 중 하나를 사고 책임자가 선택합니다.

## 버전 정책

- `ServerVersion`: 서버 배포 기능 버전
- `GameContentVersion`: 아이템·경제·퀘스트·인벤토리 공개 규칙 버전
- `MinimumClientVersion`: 보호 API에 접근 가능한 최소 Unity 버전
- `RequireVersionHeader`: 충분한 클라이언트 전환 기간 뒤 운영에서만 true로 변경

최소 버전을 올리기 전에 새 Unity 버전의 배포율을 확인합니다. 로그인·버전·콘텐츠 API는
구버전 차단에서 제외되어 사용자가 업데이트 안내와 콘텐츠 정보를 받을 수 있습니다.
